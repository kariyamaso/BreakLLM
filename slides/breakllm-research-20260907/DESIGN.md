# Design contract

## 参照と融合

Speaker Deck の「Swin Transformer (ICCV'21 Best Paper) を完璧に理解する資料」を、装飾ではなく情報の組み方の参照とする。

- 表紙：左2/3の色面、右1/3の白地（2:1）。
- 本文：白地、大きな見出しと本文、四角い箇条書き。
- 枠組み：左の細い縦線、見出し下の細線、下端の帯と右ページ番号。
- 説明：図を大きく、注釈を短く。図＋文章、図＋図、コード＋図を使い分ける。
- 注釈：淡いCyanの吹き出し。常用せず、差分を指す箇所だけに使う。

906MTGから維持するもの：

- 濃紺 `#132c96`、青 `#0054b5`、赤 `#ed3131`、ミント `#008579`。
- Noto Sans JP と、白地を活かした図表。
- 角の小さい矩形、淡い面、上辺・左辺による強調、矢印フロー。
- 数式枠、比較表、トークン列、下端の青い帯。

906MTGの太い見出し罫線は、参考資料の細い罫線へ変更。本文をすべてカードで囲まず、余白でまとまりを作る。
装飾用の大きな発光・影・無関係な図は使わない。アプリUIそのもののデザインにスライド全体を寄せない。

## 基本寸法

| 項目 | 値 |
|---|---|
| キャンバス | 1440 × 810（16:9） |
| 左右余白 | 64px |
| 左の基準線 | x=30px、1px |
| ヘッダー | 高さ102px、下線1px |
| ヘッダー後の余白 | 30px |
| 下端帯 | 高さ46px |
| 見出し | 44px / 750 |
| 本文 | 30px / 行間1.6 |
| 補足 | 24px |
| 図説明 | 19px |
| 出典 | 13px、下端帯内 |
| 表紙タイトル | 55px |

見出しは全角約26文字までを目安に1行で収める。長いタイトルは短くし、説明は本文に移す。
表紙の明示的な2〜3行だけは例外。本文を縮小して詰め込まない。

## 色の役割

| 色 | 役割 |
|---|---|
| Navy | 見出し、表紙の面、主たる文字 |
| Blue | 主系列、接続線、下端帯 |
| Cyan | 図の注釈・参照 |
| Mint | 比較対象、追加モジュール、肯定的な差分 |
| Red | 注意、負の結果、重要な変更 |
| Gray | 基準手法、補助線、補足 |

通常本文はNavy由来の濃い `#27365a`。赤の小さな文字には読みやすい派生色 `#bd2525` を使う。意味を色だけに依存させない。
CyanとMintは主に図形へ。長い本文を明るい色にしない。

## 図形・図表

- フローの矢印を文字の上に通さない。接続→ノードの順に描画する。
- 模式図は模式図と記載。モデルの性能結果を図形の装飾として作らない。
- 配置済みのアーキテクチャSVGは独自の見本。特定モデルの実装を意味しない。
- 注釈は1〜2箇所を目安とし、図や説明に重ねない。
- 図の縦横比を維持し、拡大が必要なら全体図と詳細を別ページにする。
- グラフには軸・単位・比較条件・出典。未測定は空欄や「未測定」。
- テーブルは行の細線だけを基本にする。全セルを太線で囲まない。
- コードを除き本文はプロポーショナルフォント。数値は桁を揃える。
- 他者のロゴ・所属をテンプレートのブランドとして残さない。

## 文体

「概要」「工夫点」「構成」「実装」「評価条件」「結果」「次の作業」のような簡潔な用語を使う。
宣伝的なコピー、抽象的な日本語、過剰な英語見出しを増やさない。
実装済み／設計案／評価済みを区別し、比較条件が違う値からSOTAを主張しない。

## 再利用時の品質確認

1. 作例のダミー数値・説明・日付を残していないか。
2. タイトルの改行、本文のはみ出し、図の歪み、出典の衝突がないか。
3. 図・表・本文で値と単位が一致しているか。
4. ノートを閉じた表示と一覧表示を確認したか。
5. PDFで全ページが1枚ずつ、16:9で出力されるか。
6. オフラインでもフォントと画像が表示されるか。

スライドを追加したら、全ページを画像で確認する。自動検査が通っても、図中文字の可読性や意図しない接続は目視で確認する。
